# P12 Decisions

All entries are decided by the operator under delegation (ADR-051 S-5), 2026-11-06, and tagged `DELEGATED-DEFAULT`. No register row is `OPEN` or `SOURCE-OPEN` for this phase.

| ID | Question and options | Decision and reason | Source |
|---|---|---|---|
| DD-P12-01 (`DELEGATED-DEFAULT`) | Which PageModel does the PDF come from? Options: (a) always a fresh layout, (b) always the preview's object, (c) the preview's object when it is of the current document, after comparing a fresh layout with it. | **(c).** ADR-010 §3 names the same instance and §8 names the comparison. When the deferred preview has not caught up with the last keystroke there is nothing to compare, so the fresh layout is used. | ADR-010 §3, §8, FR-PRV-02 |
| DD-P12-02 (`DELEGATED-DEFAULT`) | Which document, and which date, while an edit is unsaved? Options: (a) wait for the save, (b) export the local document, dated from the last acknowledged write. | **(b).** The user exports what the preview shows, also offline, and one click does not wait on a network. The session keeps the acknowledged `updatedAt`, so a saved document gives the same bytes from the editor and the library. `Date.now()` is rejected: it breaks ADR-010 §7. The click also flushes the debounce. | ADR-010 §7, NFR-14, FR-LIB-06, FR-PER-02 |
| DD-P12-03 (`DELEGATED-DEFAULT`) | A mismatch between the fresh layout and the preview: block the export or not? | **Write from the fresh layout, report the event, and say so in the status line.** The engine is a pure function, so the fresh result is the correct one for this document and the preview is the stale side. A blocked export would help nobody, and a silent difference is what FR-PRV-02 forbids. | ADR-010 §8, NFR-13 |
| DD-P12-04 (`DELEGATED-DEFAULT`) | FR-PDF-05's "full name + headline" and "product name". | Title is `<full name> — <headline>`, or the name alone. The separator is the one §9.2 uses between a title and an organization. Creator and Producer are `Resumiser`, the name the shell shows. Language is the document's `language`, written as the catalog's `/Lang`. Text is as typed, without template uppercase. | FR-PDF-05, §9.2 |
| DD-P12-05 (`DELEGATED-DEFAULT`) | FR-PDF-06's "letters, digits". Options: (a) ASCII, (b) Unicode. | **(b):** `\p{L}`, `\p{N}`, `\p{M}`, `-`, `_`, `.`. The product targets Ukrainian and Spanish, and combining marks are part of a letter in decomposed text. Each whitespace character becomes `-`. Leading and trailing dots go, so a title cannot make a hidden file or a path step. A title with nothing left falls back to `resume`. This uses runtime Unicode data, which ADR-010 §7 allows here: the name is not part of the PDF's bytes. | FR-PDF-06, FR-TXT-01, D15, ADR-010 §7 |
| DD-P12-06 (`DELEGATED-DEFAULT`) | How do blocked buttons explain themselves? Options: (a) native `disabled` with a hidden reason, as in P08, (b) `aria-disabled`, focusable, with a visible reason. | **(b).** FR-TYP-03 says the button explains, and a natively disabled button cannot be reached by keyboard. Blank or whitespace-only names count as missing. Unverified accounts get "Resend verification", which goes to the existing `/verify-email`. The verified state is re-read when the window regains focus, because verification happens in another tab. The gate is a product rule, not a security boundary (ADR-013, T-EP-04). | FR-TYP-03, ADR-013, ADR-036 §11, NFR-06 |
| DD-P12-07 (`DELEGATED-DEFAULT`), closes the P11 carry-in | Characters outside the bundled faces (emoji, CJK, and PT Serif's gaps). Options: (a) bundle fallback fonts, (b) block the export, (c) export, keep the typed text for copy, and tell the user. | **(c).** A CJK fallback is many megabytes against NFR-02, and PDF cannot carry colour emoji from these tools. Blocking contradicts FR-PDF-01. The PDF prints the font's empty box at the model's position, with `ActualText` holding the typed text, because the experiment showed these characters otherwise vanish on copy. The status line names up to ten of them, not counting default-ignorable ones. The preview may still show a system glyph there, as P11 recorded; line breaks stay the engine's. | NFR-07, FR-PDF-01, FR-PDF-02, P11 qa-report |
| DD-P12-08 (`DELEGATED-DEFAULT`) | NFR-07's "fonts cover Latin Extended and Cyrillic": PT Serif lacks 28 of Latin Extended-A (for example Ċ, Ĳ, Ŋ, Ŵ) and 4 of Cyrillic (Ѐ, Ѝ, ѐ, ѝ). Roboto and IBM Plex Sans cover both ranges, and all three cover Spanish, Ukrainian and Slovak. Options: (a) swap the font in the engine per character, (b) keep the font, record the gap, tell the user. | **(b).** Per-character fallback changes the engine's shaping path for a rare, optional font choice. Those letters are not in the languages NFR-07 names. A test pins the exact gap, and the characters are reported under DD-P12-07. **Recorded in the QA report as a partial for the owner.** **Overturned by DD-P12-22 after the external review.** | NFR-07, ADR-024 |
| DD-P12-09 (`DELEGATED-DEFAULT`) | FR-PDF-08's depth, and how the writer knows structure. Options: (a) re-parse the document in the writer, (b) carry `Line.block` in the model and plan a tree from it, (c) PDFKit's `subset: 'PDF/UA'`. | **(b)**, without a conformance claim. The Should names headings, lists and reading order, and those are delivered, with `Artifact` on decoration, `Figure` with the full name as alternative text on the photo, and `Link` elements holding the annotation. `subset: 'PDF/UA'` asserts conformance that nothing here validates, so the file is `tagged` and `displayTitle` only. `Line.block` is not a position, so `ENGINE_VERSION` stays (DD-P12-18). | FR-PDF-08, ADR-010 |
| DD-P12-10 (`DELEGATED-DEFAULT`) | T3's reading order against FR-TXT-02: on the page the main column comes first, while the TXT is in document order. | The tag tree and the TXT both use **document order**. FR-TXT-02's own parenthetical defines the order, and tags are what a reader and an ATS follow. The content stream keeps painting order, which `pdftotext` shows per page. | FR-TXT-02, FR-TPL-04, ADR-024 |
| DD-P12-11 (`DELEGATED-DEFAULT`) | FR-PER-05's "before each export". Options: (a) await the snapshot, (b) fire it and do not wait. | **(b).** A failure or a slow answer must not hold a Must behind a Should. It runs on Export PDF and Export TXT from the editor and the library, not on Copy as text, which writes no file. It captures the server's current version, so an edit still in the queue is not in it. | FR-PER-05, ADR-037 §7, `createSnapshot` |
| DD-P12-12 (`DELEGATED-DEFAULT`) | The photo cannot be fetched, and a crop smaller than 195 px. | A failed fetch **fails the export** with a message and `export_failed`/`photo_load`, since a PDF with a hole differs from the preview without saying so. The rendition is embedded as is: 600 px at quality 90 is 617 dpi at T1's 70 pt. A crop under 195 px gives under 200 dpi, because DD-P07-06 never upscales, and pixels invented later add no detail. Recorded as the one case FR-PDF-07 does not reach. | FR-PDF-07, DD-P07-06 |
| DD-P12-13 (`DELEGATED-DEFAULT`) | §9 corrections to P10's serializer. | (1) A contact's `mailto:`/`tel:` is hidden only when the text is the address it was derived from; "Email me" with a chosen `mailto:` prints the URL, per §9.3. (2) Empty list items, entries and whitespace-only blocks print nothing. (3) A section with a blank title prints no title line. (4) Runs of blank lines collapse to one and `\r` becomes `\n`, per §9.1. (5) The file ends with one newline, as P10's T02 has it, since §9.2's trailing blank line would leave an empty last line. | §9.1–§9.3, FR-TXT-04 |
| DD-P12-14 (`DELEGATED-DEFAULT`) | Where do FR-TXT-05 and FR-TXT-06 live? Options: (a) in the document, which needs a contract change, (b) a per-user device preference. | **(b),** behind a native `<details>` "Text options" next to the export buttons. It is stored in `localStorage` per user and cleared with the local data. It applies to Export TXT, the library, and Copy as text. | FR-TXT-05, FR-TXT-06, T-ID-06 |
| DD-P12-15 (`DELEGATED-DEFAULT`) | FR-LIB-06 needs the document, which a card does not hold. | The click calls `getResume` and runs the same path. A missing name is only known then, so it is reported in the page's status with the resume's title. An expired session goes to log in, as other card actions do. | FR-LIB-06 |
| DD-P12-16 (`DELEGATED-DEFAULT`) | NFR-03 on the reference runner. | Measured through the real route on the development laptop, the NFR-01 class, as in DD-P11-15. **Partial:** the reference CI runner stays with P15, because this operator may not push. | NFR-03, DD-P11-15 |
| DD-P12-17 (`DELEGATED-DEFAULT`) | New client event codes. | `photo_load`, `pdf_write` and `txt_write` under `export_failed`. `engine_load`, `font_load` and `layout_error` are reused. All join `ClientEventLoggedCodes`. | NFR-13, DD-P11-14 |
| DD-P12-18 (`DELEGATED-DEFAULT`) | Is `ENGINE_VERSION` bumped by `Line.block`? | **No.** Its rule is "every change to line breaks or positions", and neither changes. G7 and the unchanged G2 limits are the evidence. A cached thumbnail without `block` still paints. DD-P12-22 later moved positions for PT Serif documents with gap letters, which does bump it, to 1.1.0. | ADR-010 §7, `version.ts` |
| DD-P12-19 (`DELEGATED-DEFAULT`) | P08's W01 asserts the exports are disabled "not available yet", and the shell test's comment points to it. That behaviour is what this phase replaces. | W01 is **retargeted**, keeping its other assertions: the two buttons now exist enabled, with no such reason. DD-P08-02 scheduled this. No other existing assertion is changed to make code pass; the external review is told to check this. | DD-P08-02, CLAUDE.md test rule |
| DD-P12-20 (`DELEGATED-DEFAULT`) | T1 and T3 print names and titles uppercase, and FR-PDF-02 says copying gives "the typed characters". Options: (a) `ActualText` with the typed case, (b) copy returns what is printed. | **(b).** FR-PRV-02's automated test requires the extracted text to equal the layout's, and §9.3 lists "no template uppercase" for the TXT alone. The TXT and the metadata keep the typed case. FR-PDF-02's parenthetical is about encoding: Cyrillic and diacritics come back as themselves. | FR-PDF-02, FR-PRV-02, §6.2, §9.3 |
| DD-P12-21 (`DELEGATED-DEFAULT`) | Tier and worker tasks. | Opus, `high`, as AGENT-WORKFLOW sets. No Codex worker tasks (DD-P10-19). | AGENT-WORKFLOW |
| DD-P12-22 (`DELEGATED-DEFAULT`), **overturns DD-P12-08 and refines DD-P12-18** after the external review's major finding | PT Serif prints an empty box for letters NFR-07 names as covered, and a Must cannot be a recorded partial. Options: (a) per-character fallback, (b) drop PT Serif from the templates, which undoes ADR-024 and D-12 choices, (c) ask the owner to change NFR-07. | **(a).** A letter PT Serif lacks takes the same style of bundled Roboto, in `composeLines`, from font data only, so G7 holds. Only PT Serif has a fallback, so Roboto and IBM Plex Sans layouts are untouched and pay nothing. Selecting PT Serif also loads Roboto's four faces. The document's own font still sets the baseline. A character neither font has stays under DD-P12-07. This moves positions for such documents, so `ENGINE_VERSION` becomes 1.1.0 and joins `ClientEventLoggedEngines`. Covered now on every family: Latin-1, Latin Extended-A, basic Cyrillic. Characters beyond these (most of Latin Extended-B) are not all covered and are reported under DD-P12-07. | NFR-07, Codex review, ADR-010 §7 |
