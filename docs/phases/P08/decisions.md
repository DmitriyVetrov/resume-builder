# P08 Decisions

All entries are decided by the operator under delegation (ADR-051 S-5), 2026-11-05, and tagged `DELEGATED-DEFAULT`. No open source decision is closed here: D-05, D-06 (P07), D-07, D-11, D-17 (P01) are already accepted and implemented by this phase.

| ID | Question and options | Decision and reason | Sources |
|---|---|---|---|
| DD-P08-01 (`DELEGATED-DEFAULT`) | FR-EDT-01, 03 and 04 need a preview, but the layout engine is chosen at P10 and built in P11. Options: (a) an empty placeholder, (b) a structural draft from the document model, (c) pull layout work forward. | **(b).** An unpaginated white sheet rendering the same document in order, without hidden or empty sections, with `data-section-id` targets. It lets selection, scroll, click and live update work and be tested now, and is labelled "Draft view". P11 replaces the renderer behind the same panel. FR-EDT-01's NFR-01 clause and FR-EDT-03's page-accurate behaviour close in P11. | FR-EDT-01/03/04, ADR-010 |
| DD-P08-02 (`DELEGATED-DEFAULT`) | FR-EDT-05/06 place the Design tab and export actions in P08's layout, but their function belongs to P10 and P12. Options: omit, or show them inert. | **Show the tab with one line saying the controls are coming, and show Export PDF and Export TXT disabled with a described reason.** The layout is then final and P10 and P12 fill slots. A disabled button is honest about what is missing and is reachable by a screen reader through its description. | FR-EDT-05/06, UI-UX-DESIGN |
| DD-P08-03 (`DELEGATED-DEFAULT`) | Undo: FR-PER-04 asks for document level, FR-RTE-05 also for "inside the field". Options: (a) two stacks, field and document, (b) one document stack. | **(b).** Two stacks interleave badly: an in-field undo is itself a document change, so document undo would then undo the undo. One stack with per-field coalescing gives in-field undo that behaves as typed, and the selection moves to where the change happened. Capped at 100 steps (FR-PER-04 asks ≥ 50). | FR-PER-04, FR-RTE-05 |
| DD-P08-04 (`DELEGATED-DEFAULT`) | ADR-037 says a retry resends the stored body with its key and later edits coalesce into the next document. When a request failed with unknown outcome and the user kept typing, which goes first? | **The stored attempt, until its outcome is known.** A newer body with the old `If-Match` would answer 412 if the lost request had applied, creating a false conflict copy. Newer edits wait behind it. | ADR-037 §3–§4, DD-P07-09 |
| DD-P08-05 (`DELEGATED-DEFAULT`) | Draft storage across tabs: (a) one row per resume, (b) one row per tab with liveness, (c) lock the resume to one tab. | **(b), with Web Locks for liveness.** (a) lets two tabs overwrite each other's unsynced edits, a silent loss FR-PER-03 forbids. (c) contradicts ADR-029. Web Locks are in the last two versions of all NFR-05 browsers and need HTTPS, which NFR-08 requires. Without the API, other tabs' rows count as recoverable, which at worst gives one extra conflict copy. | FR-PER-02/03, ADR-029, T-ID-06, NFR-05 |
| DD-P08-06 (`DELEGATED-DEFAULT`) | ADR-029 covers 412 only. What about unsynced edits when the resume was trashed (409) or purged (404) elsewhere? | **Same flow: save a conflict copy first,** then show the read-only trash state or the gone state with a link to the copy. DD-P07-18 already allows `copyPhotoFromResumeId` to name a trashed resume for this case. | ADR-029, DD-P07-18, NFR-10 |
| DD-P08-07 (`DELEGATED-DEFAULT`) | ADR-037 §4 asks to report a content-free client event on a 422, but `reportClientEvents` is `x-phase: P11` and has no server yet. Options: call a missing endpoint, or defer. | **Defer the report to P11;** all other 422 behaviour ships here. P11's `PHASE.md` will pick it up from this entry and from `qa-report.md` "Deferred". | ADR-037 §4, OpenAPI `reportClientEvents` |
| DD-P08-08 (`DELEGATED-DEFAULT`) | Timing. | **Debounce 750 ms** (FR-PER-01 ≤ 1 s). **Backoff 1 s doubling to 30 s with full jitter on the upper half.** `Retry-After` wins when it is longer. | FR-PER-01, ADR-037 §4 |
| DD-P08-09 (`DELEGATED-DEFAULT`) | Drag and drop: HTML5 drag events, a library (dnd-kit), or pointer events. | **Pointer events, about 60 lines, no dependency.** HTML5 drag does not work on touch; a library adds surface for one interaction. Up and down buttons remain the keyboard path (FR-SEC-04, NFR-06). Escape cancels a drag. | FR-SEC-04/08, FR-HDR-03, NFR-06 |
| DD-P08-10 (`DELEGATED-DEFAULT`) | Photo operations increment the resume version. How do they coexist with autosave? | **Through the queue, after it drains.** Otherwise a photo write and a document write race on one version and one always loses with a false conflict. While offline the action reports that it needs a connection, and nothing is queued. | ADR-037 §4, FR-PHO-01 |
| DD-P08-11 (`DELEGATED-DEFAULT`) | Crop controls. Options: drag only, or sliders too. | **Native range inputs for zoom, horizontal and vertical, plus pointer drag on the stage.** NFR-06 names sliders; native ranges are keyboard operable and announced. The crop dialog opens after each upload, because the server's default is only a centred square. Crop is a square in v1 (contract). | FR-PHO-01, FR-PHO-05, NFR-06, OpenAPI `updatePhotoCrop` |
| DD-P08-12 (`DELEGATED-DEFAULT`, approved test exception) | P05 tests encode the placeholder this phase replaces: `routes.test.tsx` (landing links to `/resumes/fixture-id/edit`; the editor renders with no API), `editor-panels.test.tsx`, `shell-navigation.test.tsx` (no save or export button), `shell.spec.ts` (`/resumes/fixture-id/edit` makes no API call; the panels render without data). Options: keep a fake route alive, or amend. | **Amend exactly these, no assertion weakened.** FR-EDT cannot be met without `getResume`. The panel, tab, region, skip-link, axe and overflow assertions move to the editor tests against a fixture resume and stay as strict. The "no save or export button" assertion, which described an inert shell, is replaced by the disabled-export and status assertions. `/` links to the library, since no fixture route exists any more. Listed in `tests/test-results.md` for the external review. | ADR-051 S-5, FR-EDT-01/06 |
| DD-P08-13 (`DELEGATED-DEFAULT`) | T-ID-06: when and how sign-out offers removal. | **Log out checks for local data of this user. None: logs out as before. Any: a dialog offers "Remove and log out", "Keep and log out" and "Cancel", and warns when unsynced edits exist.** Removal needs an explicit choice (ADR-037 §security). A last-section ID counts as local data, so anyone who has opened a resume on this device sees the offer: T-ID-06 asks for exactly that on shared devices, and it costs one click. | T-ID-06, ADR-037 |
| DD-P08-14 (`DELEGATED-DEFAULT`) | FR-LIB-05 "last selected section": where is it kept? | **`localStorage`, key `resumiser:last-section:<userId>:<resumeId>`, value is the section ID or `header`.** T-ID-06 allows IDs only there. A deleted section falls back to the header. | FR-LIB-05, T-ID-06, DD-P07 plan |
| DD-P08-15 (`DELEGATED-DEFAULT`) | FR-SEC-09: which conversions are lossless? | **`list` ↔ `text`, `inline` ↔ `text`, `list` ↔ `inline`** when no information is lost: list → text gives one paragraph per item; text → list needs all blocks to be paragraphs or bullets without line breaks; to `inline` needs at most one line; from `inline` always works. **`entries` never converts.** A disabled option states why. Item IDs are fresh. | FR-SEC-09 (S) |
| DD-P08-16 (`DELEGATED-DEFAULT`) | Length limits count code points (DD-P01-30), but `maxLength` counts UTF-16 units, so 120 emoji would stop at 60. | **Clamp in the change handler by code points, and say so under the field when text was cut.** Total text is left to the server (R-12) and shown as the R-8 error, with no second count to keep in step. | NFR-07, NFR-12, domain-model §3 |
| DD-P08-17 (`DELEGATED-DEFAULT`) | Narrow tabs: what happens on selecting a section? | **Selecting switches to the Edit tab.** Otherwise a phone user taps and nothing visible happens. The tablist keeps the P05 markup: four tabs, hidden by CSS at ≥ 1024 px. | FR-EDT-07 |
| DD-P08-18 (`DELEGATED-DEFAULT`) | Opening a trashed resume by URL. | **A read-only notice with a link to Trash, no forms.** A trashed resume cannot be saved (R-10), and restoring from an editor URL would be a new flow. | R-10, FR-LIB-04, P07 ui-ux-design |
| DD-P08-19 (`DELEGATED-DEFAULT`) | FR-PER-05 restore: replace immediately or add a step? | **Restore applies the snapshot's document as one undoable edit** through the normal queue (contract: "send its document with `replaceResumeDocument`"). The photo is not part of a snapshot and stays. | FR-PER-05, OpenAPI `getSnapshot` |
| DD-P08-20 (`DELEGATED-DEFAULT`) | State management. ADR-050 deferred the choice. Options: a store library, React context, or a small external store. | **A small class with `useSyncExternalStore`.** One owner, testable without React, no dependency. No form library: forms are controlled from the session. | ADR-050, CLAUDE.md "explicit single ownership" |
| DD-P08-21 (`DELEGATED-DEFAULT`) | A long 5xx outage is not "Saving…" and not literally offline. FR-EDT-06 lists three texts. | **A fourth text, "Server unavailable, changes kept locally".** FR-EDT-06's three stay exact for their cases; claiming "Saving…" during an outage would be untrue. | FR-EDT-06, P5 |
| DD-P08-22 (`DELEGATED-DEFAULT`) | `P08` E2E rules for the fixture API. | **Stateful and strict, in `tests/e2e/editor-fixture.ts`:** CSRF, key, hash replay, `If-Match`, version, conflict and limit answers, with a `violations` list asserted empty after each test. Prism is stateless (P02 R-04). | P02 plan R-04, ADR-037 |
