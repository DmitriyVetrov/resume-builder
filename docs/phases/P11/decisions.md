# P11 Decisions

All entries are decided by the operator under delegation (ADR-051 S-5), 2026-11-06, and tagged `DELEGATED-DEFAULT`. No register row is `OPEN` or `SOURCE-OPEN` for this phase.

| ID | Question and options | Decision and reason | Source |
|---|---|---|---|
| DD-P11-01 (`DELEGATED-DEFAULT`) | Where does layout run while typing? Options: (a) synchronously on every edit, (b) a timer or `requestAnimationFrame`, (c) `useDeferredValue` plus `useMemo`, (d) a Web Worker. | **(c).** React renders the form first and can abandon a stale layout when the next key arrives, with no timer to tune. P10 measured 113 ms at worst for the 4-page fixture, so a worker's cost has no measured need. It stays the fallback if the NFR-01 benchmark misses. | NFR-01, ADR-010 §6 G3 |
| DD-P11-02 (`DELEGATED-DEFAULT`) | The draft view goes, and P08, P09 and P10 tests read its markup. Options: (a) keep the draft as a fallback, (b) remove it and retarget the tests. | **(b).** Two renderers of one document is what FR-PRV-02 forbids, and P08's DD-P08-01 and P10's DD-P10-02 planned the replacement. **This is a recorded exception to "a developer does not change tests":** retargeted files are `workspace.test.tsx`, `design-panel.test.tsx`, `library.test.tsx`, `engine.test.ts` (E21, E22), `tests/e2e/editor.spec.ts`, `rich-text.spec.ts`, `design.spec.ts`, `real-stack/editor-acceptance.spec.ts`, `real-stack/design-acceptance.spec.ts`. Deleted: `draft-sheet.test.tsx`, `rich-text-view.test.tsx`, whose subject is removed. The test plan maps each V test to its engine or preview successor. No assertion is dropped without a successor, and the external review is asked to check this. | DD-P08-01, DD-P10-02, CLAUDE.md non-negotiable |
| DD-P11-03 (`DELEGATED-DEFAULT`) | ADR-024 says T3 is "main 64%, sidebar 36% of the content width, gutter 16 pt", which is 100% plus a gutter. | Main is 0.64 × content width, the sidebar is what remains after the gutter. It is what the P10 draft rendered, and it keeps the main column's measure stable when the gutter is a fixed number. | ADR-024 |
| DD-P11-04 (`DELEGATED-DEFAULT`) | FR-PRV-06 does not define 100%. Options: (a) 1 pt = 1 px as in §6's measurements, (b) true size, 1 pt = 96/72 px. | **(b).** It is what "100%" means for a page, and the painter's `pt` units already give it. Fit width is the default, because the panel is usually narrower than true size. The choice is not stored: it is a view state, not part of the resume. | FR-PRV-06, §6 |
| DD-P11-05 (`DELEGATED-DEFAULT`) | How does assistive technology meet a painted page? Options: (a) hide the text and describe the page, (b) keep the text readable and overlay section buttons, (c) a parallel semantic tree. | **(b).** Pages are labelled groups ("Page 1 of 3"), runs are text in reading order, and each section has one button. (a) would hide the preview's content, and (c) is a second rendering to keep in step. Headings and lists remain in the editing forms, which are the accessible editing path. | NFR-06 |
| DD-P11-06 (`DELEGATED-DEFAULT`) | FR-PRV-08 says "section/entry", and `Selection` holds a section ID. Options: (a) section only, (b) add a transient target. | **(b).** A click resolves through line anchors. An entry opens that entry's form and scrolls to it; a list item scrolls to its row; the header opens the header form. The target is transient state on the session, not history and not stored. Keyboard activation selects the section, since each section is one tab stop. | FR-PRV-08, FR-EDT-04 |
| DD-P11-07 (`DELEGATED-DEFAULT`) | What does FR-PRV-07 highlight, and where do hints live? | Two kinds in `PageModel.hints`: `lone-title` (the §5.11 safety net) and `oversized` (PG-09). They are part of the layout result, so they are deterministic and hashed, and the PDF ignores them. The preview draws a dashed outline with a text line, so not colour alone. | FR-PRV-07, PG-09, ADR-010 §10 |
| DD-P11-08 (`DELEGATED-DEFAULT`) | FR-PRV-05's stopping rule. Options: (a) step down one value at a time, (b) the highest value that fits. | **(b),** in the spec's order: line, entry, section spacing, then font preset. Each stage first tests its minimum, then binary-searches, so a stage takes at most 5 layouts and the helper changes the least it can. If nothing fits, the document stays as it was and the panel reports it. One undo step. Margins are not on the FR's list and stay. | FR-PRV-05 |
| DD-P11-09 (`DELEGATED-DEFAULT`) | Where do thumbnails come from? | Page 1 of a real layout. The picker lays out the deferred document under each template, only while the Design tab shows. The library lays out the fetched document, for visible cards only. Cached pages are JSON and need fonts but no engine, so a cached card does not load the layout chunk. | ADR-010 §9, FR-LIB-01, FR-TPL-02 |
| DD-P11-10 (`DELEGATED-DEFAULT`) | Thumbnail cache: a new store in `resumiser-local`, or a separate database? | **A separate database, `resumiser-thumbnails`,** one row per `(userId, resumeId)` holding the version, engine version, page and photo URL. A separate database needs no migration of the store that holds unacknowledged edits, and a failure here cannot touch drafts. It counts as local data (T-ID-06), so "remove local data" clears it and a logout offers removal. Account deletion clears it too, since it holds resume text. A complete active list prunes other rows; a 404 prunes that row. Trashed cards recache on demand. | ADR-010 §9, T-ID-06 |
| DD-P11-11 (`DELEGATED-DEFAULT`) | Does the library need a batched documents endpoint (ADR-010 §6 "recorded")? | **No,** at most 3 concurrent `getResume` calls for visible cards, then the cache. 12 cards are measured against NFR-02 at 10 Mbit/s in step 7. A miss reopens this as an additive contract change, not a silent one. | NFR-02, ADR-010 §6 |
| DD-P11-12 (`DELEGATED-DEFAULT`), closes DD-P10-17 | `gzip` for `font/ttf` and scripts in the web image? | **Yes.** The engine chunk and four faces are about 1.3 MB uncompressed, over a second at 10 Mbit/s on their own. `gzip` costs a line of nginx configuration. Hashed-asset caching headers are left to P13's hardening. | NFR-02, DD-P10-17 |
| DD-P11-13 (`DELEGATED-DEFAULT`), closes DD-P10-11 | Hyphenation (FR-LAY-09, Should). Options: (a) build it with the `hyphen` patterns, (b) leave it out of v1. | **(b).** FR-PDF-02 (Must) requires that copying and searching give the typed characters, and a hyphen inserted at a line end breaks both, which matters most for ATS parsing. Text is ragged-right, so hyphenation has no justification gaps to close. The step 5 measurement records how the narrowest column reads. **The FR-LAY-09 hyphenation clause is not delivered;** it is a Should, and the owner sees it in the P15 decision table. | FR-LAY-09, FR-PDF-02, DD-P10-11 |
| DD-P11-14 (`DELEGATED-DEFAULT`), closes DD-P08-07 | What does the server do with a client event, and what does the client send? | **The server validates and writes one log line:** type, code, resume ID, engine version. No storage: NFR-13 asks for a log line. **Corrected after the external review:** the contract's patterns and the UUID format still admit chosen text, so the log takes only a code or engine version from a closed list and a resume ID the caller owns, read once per event; anything else logs as `other` while the request is still accepted as the contract says. Session and CSRF as the contract says; 30 per minute per IP as ADR-038 says; 202 with no body. **The client sends** `idempotency_key_reused` on that 422, `autosave_failed` on any other 422, and `preview_failed` on an engine, font or layout failure, once per page load per kind, and never lets a failed report reach the user. | ADR-037 §4, ADR-038, NFR-13, DD-P08-07 |
| DD-P11-15 (`DELEGATED-DEFAULT`) | G3 and G4 on the reference CI runner are carried in, but this operator may not push, so GitHub cannot run them. | **Measured on the development laptop, which NFR-01 itself names as the reference class,** through the real editor and also at 4× CPU throttle in Chromium as a margin check. The first run on GitHub stays with P15's pipeline, as DD-P10-16 already says. Recorded as a partial, not as a pass on the runner. | NFR-01, ADR-010 §6, CLAUDE.md |
| DD-P11-16 (`DELEGATED-DEFAULT`) | ADR-010 §7 forbids transcendental `Math` in geometry, and PDFKit's SVG arc conversion uses it. | Icon paths use only `M L C Z`, with cubic approximations of the P10 icons committed as numbers. G7 proves the bytes stay identical across browsers. | ADR-010 §7, FR-HDR-05 |
| DD-P11-17 (`DELEGATED-DEFAULT`), refines ADR-010 §2 | The new dense fixtures gave WebKit 1.202% on G2, over the limit, with the error growing along each line: WebKit on Linux hints advances at small sizes, so a whole-line run drifts from the model. ADR-010 §6 says a miss changes the painter. Options: (a) SVG per-glyph placement, (b) one element per word, (c) large text scaled down, (d) re-anchor long runs at intervals. | **(d).** A run over 40 characters carries `parts`, cut at a space about every 32 characters, with offsets from the same shaping as its width, and the painter places each one. (c) was tried and measured worse in all three browsers (Chromium 2.433%, Firefox 3.107%, WebKit 1.651%), since each box then snaps to the pixel grid. (d) adds about three elements per long line where (a) and (b) add dozens. Result: Chromium 0.146%, Firefox 0.388%, WebKit 0.560%. The PDF still writes whole runs, and `raster-diff.mjs` now requires all three browsers by default. | ADR-010 §2, §6, FR-PRV-02 |
| DD-P11-18 (`DELEGATED-DEFAULT`) | Adding the frozen operation trips three guards: the host inventory (P07 K01), the in-process inventory, and the log field allowlist. Options: (a) leave the endpoint out of them, (b) extend each by exactly what this phase adds. | **(b).** The inventories gain `POST /client-events` and P11's phase, and the count goes from 29 to 30. The allowlist gains `Type`, `ResumeId` and `EngineVersion`: NFR-13 asks for the resume ID, and each is a parsed value (CE09). The guard also now inspects `SafeLogs.ClientEvent`, which it could not see before, so the change adds coverage. No other assertion changes, and the external review is told. | NFR-13, ADR-038, ADR-051 S-4 |
