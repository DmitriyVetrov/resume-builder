# P04 Decisions

All decisions below are `DELEGATED-DEFAULT` under ADR-035 A-4. They refine already Accepted ADR-008, ADR-038, ADR-040 and ADR-041 for this foundation; no OPEN/SOURCE-OPEN product decision is consumed and no new ADR or contract change is required. The source specification remains authoritative.

| ID | Decision and source | Options considered | Reason |
|---|---|---|---|
| DD-P04-01 | **Readiness probes MongoDB only**, with a bounded ping; liveness checks the process only. The 200/503 bodies follow P02 OpenAPI. Sources: NFR-10; `getLiveness`, `getReadiness`; P03 Compose. | Process-only readiness; probe MongoDB; probe MongoDB plus Blob/SMTP. | MongoDB is the only required dependency wired in P04. Process-only readiness can route traffic to an unusable instance; Blob/SMTP are not yet in the host. Generic 503 hides dependency details. |
| DD-P04-02 | **Use project-reference/reflection tests** for ADR-008 F-BE-1…5. No architecture-test package in P04. Sources: ADR-008, ADR-041. | NetArchTest; ArchUnitNET; reflection/project-reference checks. | Four projects and one host need a small deterministic rule set. Reflection checks dependency direction and endpoint references without a new package. F-BE-5 also requires focused logging API/source checks and integration capture, beyond a package rule. |
| DD-P04-03 | **Use `JsonSchema.Net` for JSON Schema 2020-12 response validation and `coverlet.collector` for diagnostic coverage**, with exact NuGet pins and lockfiles chosen by the implementation role. Sources: ADR-040 §3(c), ADR-041. | `JsonSchema.Net` versus a hand-written subset; coverlet versus no collector. | Contract-driven validation needs full 2020-12 semantics; a custom validator risks accepting malformed responses. Coverage aids review but is not a pass gate, as ADR-041 states. |
| DD-P04-04 | **Typed validated Mongo options, explicit trusted proxies, global health rate limit and allow-listed structured logs.** Sources: NFR-08/09/13, ADR-038, ADR-008 F-BE-5. | Implicit environment reads; trust all forwarding headers; default request logging; explicit options/trust/log allow-list. | Explicit configuration fails safely, prevents IP spoofing and avoids accidental content logging. The host exposes no new API operation. |
| DD-P04-05 | **Serve both health operations at `/api/v1/health/live` and `/api/v1/health/ready`; do not add root aliases.** Sources: `contracts/openapi/openapi.yaml` top-level `servers: [{url: /api/v1}]` and paths `/health/live`, `/health/ready`; ADR-006 §Decision 3; review finding M-3. | Implement the resolved `/api/v1` URLs; retain root `/health/*` and ask the Contract Architect for a path-level `servers: [{url: /}]` override. | OpenAPI resolves each path against its server URL. The frozen contract and generated P05 clients already use `/api/v1`; moving the host is the smallest contract-preserving correction. Keeping root would require a Contract Architect change, compatibility review and regenerated client/mock outputs, while leaving a special unversioned health surface to maintain. |

### DD-P04-05 execution and handoff

1. **Test Engineer first (red):** update the existing HTTP tests in `backend/tests/ResumeBuilder.Api.Tests/HostTests.cs`, `LoggingTests.cs` and `ExceptionTests.cs` to call the two resolved `/api/v1/health/*` URLs, including the startup probe, rate-limit requests, query marker and exception-injection path match. Keep the rate-limit permit accounting and all privacy/error assertions. Extend the drift/inventory checks so they assert that the contract server URL `/api/v1` resolves the two P04 paths to those public URLs and that the in-box host inventory agrees on the public URLs. The raw OpenAPI path keys remain `/health/live` and `/health/ready`; do not rewrite the contract or weaken status/security/schema checks. Record the expected red result against the current root-only host.
2. **Backend Developer after red:** map only the two contracted `/api/v1/health/*` routes in `backend/src/ResumeBuilder.Api/Program.cs`, preserving operation IDs, anonymous access, global rate limiting, bodies, media types, statuses and safe logging. Update `backend/README.md` to name the public URLs. Run the focused P04 tests, full P04 suite and backend CI job, and append exact results to `tests/test-results.md`. Do not add `/health/*` aliases: they would create undocumented public operations.
3. **Deployment and other roles:** `docker-compose.yml` contains only MongoDB, Azurite and Mailpit healthchecks; `infrastructure/` has no API-host container or probe. No P04 Compose or infrastructure edit is needed. Any later API-host container, Compose, ingress or orchestrator liveness/readiness probe must use `/api/v1/health/live` or `/api/v1/health/ready` as appropriate; its owner updates that probe when it is introduced. P05 clients and mocks already consume the frozen contract, so the Frontend Developer has no P05 source change for this decision. The Code Reviewer and QA verify the full public URLs and absence of a root alias.

No paid external account or secret is needed for P04. P06/P07 may extend the readiness dependency set when they add required infrastructure, with contract-compatible public responses and tests.
