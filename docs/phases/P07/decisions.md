| DD-P07-09 (`DELEGATED-DEFAULT`) | ADR-037 stores `{key, hash, status, resource}` but leaves crash and failure behaviour open. Options: store only successes; store all outcomes; keep a hash-bound record that only replays success. | **Hash-bound record with state `in_progress`/`completed`, a 60 s lease and a reserved resource ID.** Same hash while leased → 409 with `Retry-After`; after a crash the lease expires and the retry takes over with the same reserved ID, so a create cannot duplicate. A failed attempt (4xx) wrote nothing and is released: its retry is re-evaluated, while a different body under that key stays 422. Versioned non-document writes also stamp `lastOperation` in the same atomic write, so a retry after a crash between write and completion replays rather than answering 412. Document writes keep `lastWrite` as ADR-037 says and are not blocked in flight: the race loser re-reads and replays. | ADR-037 §3; OpenAPI `Idempotency-Key`; threat model T-TA-07 |
| DD-P07-10 (`DELEGATED-DEFAULT`) | ADR-039 §3 requires the ledger entry before deletion, but a ledger entry written before the `If-Match` check could later erase live data on restore. Options: ledger first; delete first; two-phase. | **Two-phase.** Purge: version-checked write sets `purgeRequestedAt` (hidden from every read and list) → dual ledger → blobs → snapshots → document. Photo removal or replacement: version-checked write moves the old ID to `pendingPhotoRemovals` → dual ledger → blobs → pull. `ResumeLifecycleWorker` (15 min, like P06) finishes interrupted work, and a retried purge resumes it. A failure after the durable write never turns a saved write into an error; only an unfinished purge answers 5xx, because its effect is not complete. | ADR-039 §3–§4; ADR-009 §7; T-DS-03, T-ID-09 |
| DD-P07-11 (`DELEGATED-DEFAULT`) | NFR-12 limit under concurrent creates: count then insert (races), insert then compensate (false rejections), reservation counter (drifts), transaction. | **Transaction: bump a per-owner lock document, count, insert.** Write conflicts serialise concurrent creates of one owner, the count is exact and nothing can drift. ADR-004 already runs a replica set everywhere for this. | NFR-12, ADR-016, ADR-004 |
| DD-P07-12 (`DELEGATED-DEFAULT`) | Automatic snapshot semantics: capture the version before or after the write; when is the first? | **Capture the new version after the write, first on the first write, then when ≥ 10 minutes passed since the last automatic one** (`lastAutoSnapshotAt` in the same write). A failed automatic snapshot is logged content-free and never fails the acknowledged save. | FR-PER-05, ADR-037 §7, OpenAPI `createSnapshot` |
